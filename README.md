# HealthApp

**MyHealth** — полностью клиентское SPA/PWA для локального ведения дневника давления, пульса, глюкозы, веса и боли. Техническое имя проекта и репозитория — `HealthApp`; пользовательское имя установленного приложения — `MyHealth`.

## Приватность и хранение

- Медицинские записи хранятся только в IndexedDB `pressure-diary` на устройстве пользователя.
- Приложение не имеет backend, аналитики, телеметрии, рекламы и сторонних API.
- Service Worker кэширует только статические файлы приложения. Медицинские данные не попадают в HTTP Cache.
- Единственный способ вынести записи с устройства — явно запустить экспорт CSV/JSON.
- Рекомендуется регулярно сохранять JSON-копию в приложение «Файлы» или другое выбранное пользователем хранилище.

## Возможности

- единая хронология давления, пульса, глюкозы, веса и боли с фильтрами;
- локальный профиль с датой рождения, полом и ростом; текущий вес берётся из самой новой по `measuredAt` записи;
- создание, редактирование и подтверждаемое удаление записей;
- текущие и завершённые приступы боли по частям тела;
- курсы лекарств, вычисляемое расписание по частям суток, отметки приёмов, история и статистика соблюдения схемы;
- периоды 7/30/90 дней, всё время и собственный диапазон;
- обзор и подробная статистика давления, пульса, глюкозы, веса и боли;
- централизованная справочная оценка показателей без диагнозов и назначений;
- адаптивные canvas-графики без внешних библиотек;
- UTF-8 CSV, JSON backup версии 9 с настройками интерфейса и режимом Liquid Glass, импорт backup версий 1–9, добавление и транзакционная замена данных;
- запрос полного JSON backup после каждого успешного добавления, изменения или удаления; отложенный запрос повторяется при следующем запуске;
- классический и современный интерфейсы, три пользовательских режима Liquid Glass (`full`, `reduced`, `none`) с `reduced` по умолчанию, светлая/тёмная тема, Safe Area, touch targets и доступная разметка;
- постраничный вывод дневника по 60 событий при сохранении расчётов по всем данным.

## Локальная проверка

Приложение не требует сборки. Не открывайте `index.html` напрямую через `file://`: Service Worker и ES-модули должны обслуживаться по HTTP(S).

Из корня проекта запустите любой статический сервер, например:

```powershell
python -m http.server 8080
```

Откройте `http://localhost:8080/`. Для проверки на другом устройстве нужен HTTPS-хостинг; Service Worker разрешён на `localhost`, но не на обычном HTTP-адресе локальной сети.

Необязательные автоматические проверки не устанавливают зависимостей и запускаются командой `npm test`.

### Быстрая функциональная проверка

1. Создайте измерение давления и текущий приступ боли.
2. Завершите приступ с изменённым временем окончания.
3. Отредактируйте записи и проверьте фильтры дневника.
4. Откройте все три раздела статистики и смените период.
5. Экспортируйте JSON, удалите записи и восстановите их через «Заменить все данные».
6. Экспортируйте CSV и проверьте кириллицу, запятые, кавычки и переносы строк.
7. В DevTools → Application убедитесь, что IndexedDB называется `pressure-diary`, а Cache Storage содержит только app shell.
8. В DevTools → Network выполните CRUD, статистику, импорт и экспорт: запросов с медицинскими значениями быть не должно.

## Публикация в GitHub Pages

1. Создайте на GitHub **публичный** репозиторий `HealthApp` и загрузите содержимое этого каталога в корень репозитория.
2. Откройте `Settings → Pages`.
3. В разделе `Build and deployment` выберите `Source → Deploy from a branch`.
4. Выберите ветку `main`, каталог `/(root)` и нажмите `Save`.
5. Файл `.nojekyll` уже включён в проект: он отключает обработку готовой статики генератором Jekyll.
6. Дождитесь завершения публикации и откройте HTTPS-адрес вида `https://<owner>.github.io/HealthApp/`.
7. После первого открытия перезагрузите страницу один раз, чтобы убедиться, что Service Worker активирован и app shell закэширован.

Актуальные настройки публикации описаны в [официальной документации GitHub Pages](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

Все пути в проекте относительные (`./...`), поэтому приложение рассчитано на размещение как в корне домена, так и в подпапке репозитория.

## Checklist для iPhone / iOS 18

1. Откройте HTTPS-адрес в Safari при включённом интернете и дождитесь полной загрузки.
2. Нажмите «Поделиться» → «На экран Домой»; под иконкой должно отображаться `MyHealth`.
3. Запустите приложение с Home Screen, создайте несколько записей и полностью закройте его.
4. Включите Airplane Mode, убедитесь, что Wi‑Fi также выключен, и снова запустите `MyHealth`.
5. Без сети проверьте просмотр, добавление, редактирование, удаление, фильтры, завершение приступа, статистику, графики и импорт/экспорт.
6. Верните интернет, опубликуйте новую версию статических файлов и убедитесь после обновления, что прежние записи IndexedDB сохранились.

## Обновление приложения

При изменении любого файла app shell увеличьте версию `CACHE_NAME` в `sw.js`, например с `health-app-static-v8` до `health-app-static-v9`. Новый Service Worker удаляет только прежние кэши с префиксом `health-app-static-` и никогда не удаляет IndexedDB.
